# 记忆召回评测集说明

给 QQ 机器人（`仓库根目录\companion_brain.py`）的记忆召回写的一套**可重复**评测：
自己造一份合成语料当"记忆库"，拿 50 道带标准答案的中文问题去考它，
一组数字就能回答"这次改动让记忆变好还是变坏了"。

- 脚本：`tools/eval_memory.py`（唯一入口，单文件，不依赖任何评测框架）
- 本文：怎么跑、题目怎么分、数字怎么读、怎么加题、有什么局限

设计上只做一件事：**只读**。评测永远在临时库里跑，正式库一个字节都不碰。

---

## 1. 跑起来

```powershell
cd <仓库根>

# 最常用：两种召回策略各跑一遍，出对比表（约 1.5 秒）
python tools/eval_memory.py --auto

# 机器可读（只有 JSON，没有表格，适合挂 CI 或存基线）
python tools/eval_memory.py --auto --json

# 看每道题两种模式各排第几
python tools/eval_memory.py --auto --verbose

# 看拒答阈值放松/收紧分别要付多少代价
python tools/eval_memory.py --auto --sweep

# 对真实库做只读冒烟（不改一行，跑完自动校验文件大小/时间戳）
python tools/eval_memory.py --db brain.db
```

脚本自己把仓库根塞进 `sys.path`，所以 `PYTHONPATH` 不设也能跑；
但如果你在别的目录下调用，仍然建议 `$env:PYTHONPATH` 指向仓库根。

参数一览：

| 参数 | 作用 |
| --- | --- |
| `--auto` | 同时跑「纯向量基线」和「向量+关键词融合」，并输出差值表 |
| `--json` | 输出 JSON（`meta` / `modes.vector` / `modes.fuse` / `comparison`），不输出表格 |
| `--db PATH` | 换成真实库做只读冒烟（3 条查询，只打印结果，不计指标） |
| `--k N` | 召回条数上限，默认 5（Hit@k 跟着变） |
| `--alpha X` | 关键词权重，默认 0.3 |
| `--provider {auto,heuristic}` | `auto`=优先本地 bge 模型；`heuristic`=强制字符哈希兜底（离线自检用） |
| `--tau X` | 手动指定拒答阈值，覆盖自动标定（`--tau 0` 等于关掉门控） |
| `--smoke-tau X` | 真实库冒烟用的阈值，默认 0.10 |
| `--verbose` | 逐题并排打印两模式的排名 |
| `--sweep` | 阈值扫描表 |
| `--keep-tmp` | 保留临时库，方便手工 `sqlite3` 进去看 |

退出码：`0` 正常；`2` 库/表找不到；`1` 真实库冒烟的只读校验失败（文件被改了）。

## 2. 语料长什么样

语料是**手写的**，不是从聊天记录里抽的。21 次对话（S01–S21，2025-09-02 到 2025-12-24），
共 92 条记忆，模拟一对情侣/朋友大半年的聊天里 Bot 会记下来的那些事：

- 人：室友、弟弟、妈妈、同事
- 事：搬家、跳槽、出差、吵架和好、看演出、办健身卡
- 物：猫（先后两个名字）、吉他、多肉、手机、茶叶
- 时间：每条正文里都带日期，问"哪天"才有答案

其中 **9 条已被新事实替代**（`status='superseded'`，`superseded_by` 指向新记忆）：
"蓝色光标"被"小红书"替代、"汤圆"被"布丁"替代、"长直发"被"短发红棕"替代……
这就是知识更新题的考点——**旧的那条不该再被召回**。

`--keep-tmp` 时可以进临时库看：

```sql
SELECT id, status, content FROM memories ORDER BY id;
```

语料写在 `SESSIONS` 里，每条记忆是 `(键, 正文, importance, emo_salience)`：
键（`m0902a` 这种，日期+序号）是题目引用记忆的唯一凭据，`importance` / `emo_salience`
是写入时的评分，会进综合分。

## 3. 50 道题怎么分

五类各 10 道，总 50。每条题除了问题，还带三种标注：

| 字段 | 含义 |
| --- | --- |
| `gold` | 应该被召回的记忆键（拒答题为空） |
| `hops` | 跨会话题的"另一跳"（只用于自检：线索和答案确实分居两次对话） |
| `decoys` | 已知的强干扰项（长得像但不是答案，用来观察会不会被带偏） |
| `abstain` | 该不该拒答 |

### 信息抽取（E1–E10）

一句话里就有答案，考"能不能把原话找回来"。

> 她养的那只猫是什么花色的？ → 三花
> 她弟弟叫什么名字？ → 陈宇航
> 她从杭州带回来的茶叶是什么？ → 龙井

### 跨会话推理（X1–X10）

答案和线索分居两次对话，一次只说了半个，考"能不能把两条拼起来"。

> 她一直想去、有洱海的那个地方是哪儿？ → 10 月说"想去大理"，12 月只说"看海"
> 她弟弟明年什么时候来北京实习？ → 9 月知道有弟弟，12 月才知道时间

每道 X 题都强制要求 `hops` 与 `gold` 属于不同 session，自检会拒绝写错的题。

### 时间推理（T1–T10）

问"哪天/什么时候"，干扰项是**同一次对话里的另一条**（吵架那条 vs 和好那条）。

> 我们上次吵架是哪天？ → 12 月 5 日（不是和好那天）
> 她什么时候投的小红书简历？ → 10 月 24 日（不是入职那天）

### 知识更新（K1–K10）

问"现在"，而旧事实已经被替代。因为失效记忆在候选池里就被过滤掉了，
这一类实际考的是"新事实能不能浮上来、别被别的相似记忆挤下去"。

> 她现在在哪家公司上班？ → 小红书（旧：蓝色光标）
> 她的猫现在叫什么名字？ → 布丁（旧：汤圆）

### 拒答（R1–R10）

语料里**没有这个事实**，正确行为是"我不记得"，不是硬凑一条。
题目都是"这个话题有记录、但这个属性没提过"——只有猫没有狗、只知道自己的生日不知道爸妈的。

> 她养的那只狗叫什么名字？ → 拒答
> 她的护照什么时候过期？ → 拒答（只说过怕坐飞机）

> 这一类是整份评测里最难的：它考的不是检索，而是"没有证据时敢不敢承认"。

## 4. 指标怎么算

| 指标 | 算法 | 看什么 |
| --- | --- | --- |
| Hit@1 / @3 / @5 | `gold` 里任意一条排进前 1/3/5 的题目占比 | 排序准不准 |
| MRR@5 | `1/排名` 的平均（没进前 5 记 0） | 排第一的重要性 |
| 拒答正确率 | 10 道 R 题里"门控后返回 0 条"的比例 | 敢不敢说不知道 |
| 门控误伤 | 40 道检索题里被同一个门控挡掉的道数 | 上面那个"敢"要付多少钱 |
| 端到端正确率 | 门控后仍命中 + 正确拒答，除以 50 | 一套配置最终答对多少 |

**排序和拒答是两套动作，刻意分开算：**

- Hit@k / MRR **不加门控**。加了门控，排名指标就被阈值污染了，
  调阈值能"提高"或"降低" Hit@5，那它就不再是排序质量。
- 拒答正确率**才用门控**：`max(相关度) < tau` 就返回空。
- 门控误伤把代价摆出来：拒答率永远是阈值调出来的，只看拒答率会以为"已经 100% 了"，
  其实是把一批能答的题一起挡了。

`--auto` 时还会输出「融合 − 基线」的差值表，单位是百分点。

## 5. 打分公式

召回分两步：先算"这条记忆和问题有多相关"，再加记忆自身的先验。

```
相关性 rel = (1 - alpha) * sim_norm + alpha * kw_cov        alpha = 0.3
综合分 score = 0.80 * rel + 0.22 * importance
                        + 0.12 * exp(-天数 / 30)
                        + 0.11 * emo_salience
```

和生产的 `Brain.recall()` 同构（`0.55*sim + 0.25*kw + 0.22*importance + 0.12*recency + 0.11*emo`），
只是把前两项合成 `0.80 * rel`，这样两种模式的差别就只剩"关键词那一路有没有开"。

**为什么要有 `sim_norm`。** bge-small-zh 对"任意两句中文"都给 0.4 以上的余弦，
直接拿余弦算分，所有候选挤在 0.4–0.7，先验项（importance/recency）反而成了主导。
所以先减基线再拉伸：

```
sim_norm = (cos - 0.40) / 0.28        # bge 稠密向量
sim_norm = (cos - 0.00) / 1.00        # heuristic 兜底（它没有这个底分）
```

0.40 / 0.28 不是拍的，是量出来的：本语料上不相关约 0.30–0.45，相关约 0.52–0.69
（gold 命中位的中位数 0.576、下四分位 0.527）。

**为什么不用真的 `Brain`。** 实例化 `Brain` 会往 `backups/memory`
写备份、读那边的设置，还会因为没配云端 key 退化成字面重叠——评测就变成在测别的东西了。
所以这里把打分形状照抄一遍，用同一个 `whalegirl.fts`、同一个向量模型，可控、可重复、只读。

关键词那一路：`whalegirl.fts.search()` 拿 BM25，再乘一个 IDF 覆盖率
（查询里的词有多少被这条记忆覆盖），覆盖率低于 `0.03` 的直接丢掉——
0.03 是"只撞上一两个常见字"和"真的撞上了实体词"的分界，定高了会把"芒果过敏"
这种只靠一个词就命中的题误杀（实测 E1 的覆盖率只有 0.076）。

## 6. 拒答阈值怎么定

阈值不能写死，也不能凭感觉：两种模式的相关度分布量级不同，共用一个常数等于偏袒一方。
所以每次运行都用 **18 道校准题**（10 有解 + 8 无解）现标一个：

1. 对每道校准题算出候选池里最高的相关度；
2. 把所有分点当候选切点，逐个算"无解题挡住的比例"（TNR）和"有解题保住的比例"（TPR）；
3. 取平衡准确率 `(TNR+TPR)/2` 最高的那个切点，打平时选更保守的。

输出里会写明这次标到多少、TNR/TPR 各多少。校准题**不计入 50 题、不进任何指标**，
也不允许引用失效记忆（自检会拦）。

两个必须知道的点：

- **无解校准题要和 R 题同分布**。早期版本用了"明天股市会涨吗"这种完全跑题的句子，
  标出来的 tau 只有 0.14，R 题的拒答率看着漂亮，其实是假的——真实分布里
  "她爸妈的生日"和"她的生日"余弦能到 0.55。
- **中文向量的两边分布是重叠的**，没有哪个阈值能两全。所以脚本同时报 TPR 和误伤数，
  而不是只报一个"拒答 100%"。想看全貌就 `--sweep`：

```
|  tau | 拒答正确 | 误伤能答题 |
| 0.30 |     8/10 |       5/40 |
| 0.35 |    10/10 |       6/40 |
| 0.45 |    10/10 |      12/40 |
```

改动语料或换向量模型之后，tau 会自己重标，不用手改常数。
只想看排序质量时可以 `--tau 0` 把门控彻底关掉。

## 7. 融合策略

两模式跑的是同一份代码、同一份语料、同一套先验，唯一差别是关键词那一路开不开：

```python
# 纯向量基线：kw_rows = []
# 向量+关键词融合：
kw_rows = [(记忆id, bm25归一化 * IDF覆盖率)]   # 覆盖率 < 0.03 丢掉
fused   = fts.fuse(vec_rows, kw_rows, alpha=0.3)
```

`fts.fuse` 是生产里现成的函数（`alpha` 越大越信关键词），
`vec_rows` 直接给 `sim_norm`（已归一化到 0–1），所以两路在同一个量级上加权。

注意 `fts.search()` 返回的 BM25 是**按每次查询的最大值归一化**的（永远有一条 1.0），
所以"关键词命中"只能表示"这条是本次最像的"，不能表示"真的很像"；
乘上覆盖率正是为了把"整条查询只撞上一个常见字"的情况压下去。

## 8. 只读保证

三重：

1. **临时库**：`tempfile.mkdtemp(prefix="eval_memory_")` 下建一个只有 `memories` 表的库，
   跑完 `shutil.rmtree`（`--keep-tmp` 除外）。建库/写库前有 `_forbid_write()`，
   目标是 `brain.db` 就直接 `SystemExit`。
2. **真实库冒烟**：`sqlite3.connect("file:...?mode=ro", uri=True)` 只读打开，
   FTS 索引建在 `temp.mem_fts`（temp schema），SQLite 允许只读连接写 temp 库，
   主库文件连 journal 都不会产生。跑完对比文件大小和 `mtime_ns`，变了就返回 1。
3. **不碰 `whalegirl/*`**：只 import，不改。也不实例化 `Brain`（它有自己的备份和设置读写）。

## 9. 怎么加题

改 `QUESTIONS`，一行一道：

```python
_q("E11", "信息抽取", "她的工位在几层？", ["m1103a"], note="十二层"),
_q("X11", "跨会话推理", "……", ["m1218d"], hops=["m0915a"], decoys=["m0915b"]),
_q("R11", "拒答", "她家的门牌号是多少？", abstain=True, decoys=["m1006a"]),
```

`validate()` 会在开跑前拦下这些错误：

- 总数不是 50、某类不是 10 道、题号重复
- 拒答题带了 `gold`，或非拒答题没有 `gold`
- `gold`/`hops` 引用了不存在的键，或引用了**已失效**的记忆（那题永远不可能命中）
- 跨会话题没有 `hops`，或 `hops` 和 `gold` 落在同一个 session
- `decoys` 引用了不存在的键（`decoys` 允许是失效记忆，那种本来就不该进候选池）
- 校准题引用了失效记忆

加记忆就改 `SESSIONS`：`{"id": "S22", "date": "2025-12-30", "clock": "21:10", "turns": [...]}`，
要标"被替代"就往 `SUPERSEDED` 里加 `"旧键": "新键"`。

写题时的两个坑：

- **金标记忆里要有问题的关键词**。问题问"在哪家公司上班"，金标正文里就得出现"公司"，
  否则关键词那一路天生就输，比较不公平（第一版就因为正文写了"入职小红书"没写"公司"而误判）。
- **拒答题别问成"属性缺失"以外的形态**。问"她爸妈生日"是可以的（考的是敢不敢承认），
  但别指望检索层能分辨——见下一节。

怎么读：

- 融合在**知识更新**上确实补上了纯向量漏掉的那题（K5：`× → 4`），Hit@5 90% → 100%；
  信息抽取的 MRR 也高一点（E1 从第 3 名升到第 2 名）。
- 代价是**跨会话推理**掉了 10 个点：X5（3→4）、X7（1→2）被关键词那一路挤下去了——
  这两题的问法里出现的词，恰好也在别的记忆里出现。
- 拒答两边都是 100%，但**这不代表融合更会拒答**：两模式的拒答曲线几乎重合
  （tau≈0.35 时两边都能做到 10/10，误伤 6–8/40，融合少两道），
  瓶颈是向量模型的底噪，不是关键词——`--sweep` 能直接看到这一点。
- 端到端都是 78%，低于 Hit@5 的 95%：差额就是门控误伤——为了"该拒的都拒"，
  有 10 道能答的题被挡了。这是安全阈值的真实代价，不该藏起来。

单独验一下兜底路径（没有向量模型时还能跑）：

```
$ ... --auto --provider heuristic
向量：heuristic [启发式兜底]
纯向量基线  总体 Hit@5 35.0%  端到端 24.0%
融合        总体 Hit@5 50.0%  端到端 42.0%（+15.0 / +18.0）
```

35% vs 95% 就是"有没有真向量模型"的差距；离线环境跑出来的数字别拿去当真。
不过这里有个有用的观察：**向量越弱，关键词那一路越值钱**——bge 下融合只 +2.5 个 Hit@5，
换成哈希兜底就是 +15.0。以后想验证"要不要上关键词"，这份对比就是现成的证据。

## 11. 已知局限

1. **绝对分数不代表线上水平**。语料和题目都是手写的、互相配套，95% 是"这套题上"的成绩，
   价值在于**同一平台上的相对比较和回归**，不是"线上能答对 95%"。
2. **样本小**。每类 10 道，一道题就是 10 个百分点；差 1 道别当成结论。
3. **拒答是端到端能力，不是检索能力**。"她爸妈的生日"和"她的生日"在向量空间里就是近的，
   检索层分不开，正确答案要靠生成层说"我只记得你自己的生日"。
   这一类现在测的是"检索层在安全阈值下会不会硬凑"，别过度解读。
4. **只测召回，不测生成**。答案对不对、语气像不像，这份评测管不了。
5. **模型相关**。换向量模型、换维度，`sim_norm` 的基线和量程要重新量（见第 5 节），
   tau 也会自己重标。换完记得重跑一遍，把新基线记下来。
6. **时间基准是写死的**（`REF_NOW = 2026-01-05`）。语料日期都在这之前，
   新近度项才稳定；加更晚的记忆要同步改这个基准。
